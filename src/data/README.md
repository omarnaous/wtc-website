# Data

## These files are the floor, not the shop

Everything here is what the site falls back to. The live shop reads from D1,
and the dashboard at `/admin` is where it is edited — Home → *Import the
catalogue* copies these files into the database once, and after that the
database wins for anything that has been touched.

Editing a file here still matters in three cases: a brand-new environment
before the import, the GitHub Pages export (no database at all), and the
photography and sampled colours, which the import refreshes from these files
every time it runs.

`images.json` is generated by `npm run images` and lists everything in
`public/` for the dashboard's image picker — re-run it after adding
photography.

## Strap Studio photography

`strap-photos.json` and `public/products/strap-photos/` are generated:

```bash
npm run strap-photos                    # all sets
npm run strap-photos mission-to-mars    # one set
```

Each frame gets two outputs: the watch with its studio background flood-filled
away (`scripts/lib/cutout.mjs`) so it sits on the page rather than in a light
box, and a square swatch cut from the strap below the case, wide enough to
catch both lines of stitching.

The cutout walls off the column the strap occupies before it fills. Without
that, a white strap — which is within a couple of RGB units of the `#f5f5f5`
background — gets erased from the frame edge inwards.

**These photographs belong to Wristbuddys**, who sell aftermarket MoonSwatch
straps — i.e. a competitor. They are fine for a design preview and not fine
for a live storefront. Replacing them means reshooting each watch on each
strap from a fixed camera position; nothing else in the code has to change,
since the effect only depends on the watch landing in the same place in every
frame of a set.

## Re-sampling colours

The vector watch in the Strap Studio is drawn from `palettes.json`, not from
the photographs, so it can animate a strap change. To regenerate after adding
product images:

```bash
npm run palette
```

The script finds the case edge on each packshot and walks inward, so it reads
the true Bioceramic flank colour rather than the bezel next to it. Check the
output against a few photos after adding references.

## Instagram

The homepage grid currently shows the six most recent reels, and
`public/brand/logo.png` is the real profile picture. Both were imported from
the profile.

`curl` on a profile gets a JS shell with no post data, but the page *renders*
the grid client-side, so the shortcodes and thumbnails are readable from the
DOM. To refresh:

1. Open `https://www.instagram.com/watchtradechronicles/` in a browser.
2. Paste `scripts/ig-capture.js` into the console.
3. Save its output over `scripts/ig-raw.json`.
4. `npm run instagram:import`

Thumbnails are downloaded into `public/instagram/` rather than hot-linked:
Instagram's CDN URLs carry a signature that expires within days, so linking
them directly would break the page quietly a week later.

**This is a scrape, and scrapes rot.** The durable path is the Graph API —
`npm run instagram` is already written for it and needs no manual step, but it
requires a Business/Creator account linked to a Facebook Page and a long-lived
access token:

```bash
INSTAGRAM_TOKEN=... INSTAGRAM_USER_ID=... npm run instagram
```

The Basic Display API was retired in December 2024, so there is no simpler
supported route.

## Adding a collection

A collection is a brand partnership — the top level of the catalogue, and what
the homepage tiles link into. `Family` ("Classics", "Moonphase", …) is the
series *inside* a collection, and shows up as the "Series" filter.

1. Add an entry to `collections` in `collections.ts` — id, name, blurb, an
   accent colour, and optionally `heroSlug` (the product whose photo fronts
   the tile).
2. Set `collection: "<id>"` on the products that belong to it in
   `products.ts`. Anything without one defaults to `omega-swatch`.

That is the whole change. The homepage tile, the `?collection=` filter, the
catalogue chip and the footer link all read from that array. A collection with
no products yet renders as "Coming soon" and links to WhatsApp instead of to an
empty catalogue.

**`ap-swatch` holds the Royal Pop** — Audemars Piguet × Swatch, eight
Bioceramic pocket watches released May 2026. Its tile reads "Coming soon"
until their photography is on disk (see *Adding a product*).

## Adding a product

1. Add a seed object to `seeds` in `products.ts`.
2. `npm run watches` — downloads the three packshots for any reference that
   is missing them (`https://static.swatch.com/images/product/SKU/sa200/SKU_sa200_er003m.png`),
   then re-samples colours, rebuilds thumbnails and the image manifest.
   Anything the CDN does not have, drop in by hand as
   `public/products/watches/SKU_sa200.png`, `_sa300.png`, `_sa000.png` and
   run `npm run images`.

A seed whose `sa200` is not in `images.json` is left off the site entirely,
so a reference can be added before its photography without showing a broken
image. The ten added with WTC's price list (the Moon and Neptune Moonshine
Gold missions and the Royal Pop) are waiting on exactly that.
